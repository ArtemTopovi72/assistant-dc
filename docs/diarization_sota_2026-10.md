# Транскрибация по ролям: SOTA на 2026-10-04 (50 поисков) и что это значит для нас

## Что у нас есть
`voice/diarize.py`: Nemotron-3-Diarization (отдельный venv, CPU) → ходы (turns) → GigaAM по каждому ходу с отступом 0.15 с → «Спикер N: …».
Включено для: пересланных видео, обычных видео и кружков, видео по ссылке (с 10-04). Голосовые без диаризации.

## Главные выводы
1. **Диаризатор у нас уже лучший из открытых.** Nemotron-3-Diarization — №1 в VoiceArena Diarization-Bench (14.72% DER; 12.73% на офлайн-буфере 30.4 с), до 8 говорящих. Альтернативы: DiariZen (AMI 13.9), pyannote community-1 (AMI 17.0, есть `exclusive_speaker_diarization` для стыковки со словами ASR). Менять нет смысла.
2. **Наш приём «диаризация → ASR по ходу, отступ 0.15 с» — рекомендуемая практика.** Слабые места: теряется контекст между ходами, слово на границе хода режется, перекрытие речи не разобрано (одно слово = один спикер).
3. **LLM-коррекция меток (DiarizationLM, TPST)** снижает ошибку слов-спикеров на 45–55% (дообученная PaLM-2-S, Fisher/Callhome). Ошибки, которые чинит: хвост фразы у чужого спикера, слитые короткие реплики, перебивания. Без дообучения эффект не подтверждён — нужен замер.
4. **Короткие реплики (<1 с, «ага», «да») дают шумные эмбеддинги и плодят «фантомных» спикеров.** Практика: не заводить нового спикера по <1 с, приписывать ближайшему. У нас `MIN_TURN = 0.6`: такие обрывки просто выкидываются (`turns()`), то есть «ага» пропадает, но фантомов нет.
5. **Имена/роли:** «Спикер 1» → имя возможно только если имя прозвучало в транскрипте (AssemblyAI-подобный Speaker Identification, ~87% на ручной разметке). Заголовок и описание видео — хороший контекст для имён и терминов (hotwords).
6. **Сквозные модели (один проход «кто/когда/что»):** MOSS-Transcribe-Diarize 0.9B (русский входит в MLC-SLM, до 90 мин, лёгкая), VibeVoice-ASR (60 мин, 50+ языков, хотворды), Dixtral (cpWER 15.4% против 44.4% у Gemini 3 Flash на AMI/NOTSOFAR). Для русского реальных WER нет — только замерять самим. Gemma 4: диаризация только у 12B, аудио ≤30 с, у E2B/E4B диаризации нет.
7. **Русский ASR:** GigaAM-v3 RNNT сильно лучше Whisper на чистой речи (1.5% против 12.8% WER на Golos Crowd), хуже на смеси RU+EN (IT-термины), где выигрывает Qwen3-ASR. Оставляем GigaAM; запасной вариант при латинице — Qwen3-ASR.
8. **Музыка в YouTube-роликах:** Demucs-выделение вокала перед диаризацией заметно снижает DER (на бенгальском −12 п.п.), применять только к роликам с музыкой.
9. **Длинные ролики:** главная проблема — перестановка меток между кусками. Решение из JEDIS-LLM: «кэш подсказок спикера» (по одному примеру на спикера в начале каждого куска) или единые эмбеддинги. Относится к нашим длинным видео по частям.
10. **Видео-сигналы (лицо, active speaker detection: TalkNet / LR-ASD, OCR имён)** помогают для кино и сходных голосов, но дорого. Не нужно, пока нет жалоб.
11. **Метрика:** `meeteval` (cpWER/tcpWER) — собрать маленький набор из 5–10 русских клипов и мерить им.

## План (по убыванию пользы / цены)
- [x] A. Проход LLM «Спикер N → имя/роль» по размеченному транскрипту, только если имя есть в тексте/заголовке; иначе оставить «Спикер N». Промпт без дообучения, один вызов.
- [ ] B. Замер MOSS-Transcribe-Diarize 0.9B на 5–10 русских клипах против текущего конвейера по cpWER (meeteval). Если лучше — заменить «диаризатор + ASR» одним проходом.
- [ ] C. LLM-коррекция границ реплик (DiarizationLM-стиль) с TPST-проверкой, что слова не изменились. Только после замера выигрыша.
- [ ] D. Demucs только для видео с музыкой (детектор по доле музыки).
- [ ] E. Метки при длинных видео по частям: передавать «образцы спикеров» между кусками.
