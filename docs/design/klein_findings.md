# FLUX.3 Image Klein: заметки из веба (итеративно)

Формат: номер поиска, запрос, находки, что применить у нас (боксы, перерисовка/правки).

## Итерация 1 (поиски 1-3: промпт с боксами, правки, ReferenceMultiLatent)
- Формат боксов подтверждён: [top, left, bottom, right] на сетке 0-1000, JSON-список в КОНЦЕ описания сцены; элементы в тексте помечены тегами (= наш `<id>`). Источник: segmind, mind-verse, comfyui.nomadoor.
- `color_palette` модель ИГНОРИРУЕТ (не тратить токены; у нас `caption_to_prompt` его уже не пишет).
- Боксы — мягкая подсказка, не маска. Метка бокса — короткое существительное в единственном числе.
- Боксы работают и в ПРАВКАХ: исходный бокс + целевой бокс = «перенести объект». Идея для нашей перерисовки: правка по боксу вместо маски.
- Бокс-промпты лучше, когда их пишет LLM, а не встроенный upsampler (мы так и делаем — наш планировщик).
- Правки: несколько референсов адресуются тегами `<ref_image_0>`, `<ref_image_1>` в тексте инструкции. У нас в `klein.edit_workflow` теги НЕ пишутся -> TODO: в инструкции ссылаться на референсы так (перенос одежды/объекта).
- Инструкция — по-английски, называть только то, что меняется; остальное сцена держит сама.
- BFL рекомендует prompt upsampler для правок по референсам («без него нестабильно»); для t2i менее полезен.
- Distilled: 4-16 шагов, cfg 1; ComfyUI >= 0.41.0 (у нас так).
- Consistency LoRA 0.8 в FLUX.2-версии (у нас 1.0 для flux3 — проверить 0.8 на сетке).
- ReferenceMultiLatent: поднятие внутреннего megapixel даёт детали за время/память; первая картинка = якорь сцены.

## Итерация 2 (поиски 4-7: офиц. ComfyUI-док, mind-verse, кириллица)
- **КЛЮЧЕВОЕ для правок: в промпте правки пишут ПОЛНОЕ описание результата, а не команду.** Шаблон BFL: «In <ref_image_0>, change the dress color <obj_1> to red». То есть ссылка на картинку тегом + тег объекта + что поменять. У нас сейчас голая инструкция без тегов.
- **Layout-правка существующей картинки (мощно для перерисовки по боксам):** у каждого объекта в JSON-таблице есть `source` (например `ref_image_0`), `src_bbox` (где объект на исходнике) и `tgt_bbox` (где должен стоять в результате). Одинаковые src_bbox и tgt_bbox = «держи регион на месте» (фон). Перенос/ресайз/добавление объекта = другой tgt_bbox. Это замена нашей маск/inpaint-перерисовки.
- Референсы идут и в positive, и в negative (ReferenceMultiLatent это делает; мы так и строим).
- Размер референса: шаблоны сжимают до ~1 MP; нативный (до ~16 MP в пайплайне BFL) сохраняет детали, но дороже. Мы: Consistency + "keep resolution".
- Full-чекпойнт: t2i 50 шагов cfg 3.5; правка: 50 шагов guidance 1. Distilled: 4-16 шагов, cfg фиксирован 1 (у нас 16).
- prompt upsampler у BFL — Qwen3.5-9B (w4a8) как отдельный энкодер; можно отключать. Нам не нужен: у нас LLM-планировщик.
- На >24 ГБ рекомендуют bf16: «точнее следует длинным промптам». У нас 24 ГБ -> int8 (бенч: bf16 13 с vs int8 6 с; качество текста мы не сравнивали -> TODO A/B на длинных русских промптах).
- Режим layout без референса: 4336 токенов против 4256 — боксы почти бесплатны; каждый референс добавляет токены/латентность.
- Кириллица: офиц. гайда нет. Общие советы (fal, FLUX.2 klein): точный текст в кавычках, CAPS в промпте -> CAPS на картинке, 2-5 слов надёжны, длиннее — больше ошибок; фон под текстом проще; указывать шрифт/цвет/место.

## Итерация 3 (поиски 8-11: Enhancer, distilled vs base, int8 vs bf16, nomadoor)

## Итерация 4 (исходники ComfyUI 0.41.0 + официальные шаблоны BFL — САМОЕ ЦЕННОЕ)
Файлы: нода `Flux3LayoutPrompt` (ComfyUI comfy_extras/nodes_flux.py), шаблоны flux3_klein_*_t2i/i2i/mi2i.json (E:\klein_dl\workflows), системные промпты апсемплера BFL сохранены в `docs/design/klein_bfl_upsampler_prompts.txt` (опубликованы BFL на HF black-forest-labs/flux-3-image-klein-pup).
- Наш граф совпадает с шаблоном (KSampler euler/simple, cfg 1, 16 шагов, ModelSamplingFlux mu=2.77259; Base-шаблон: 50 шагов, **cfg 4.0**, а не 3.5).
- **alpha (сдвиг таймстепа)**: шаблон по умолчанию 16 (mu=ln16), но «референс модели 6.93» (mu=ln 6.93=1.936); больше alpha = больше шагов на высоком шуме. -> A/B alpha 6.93 vs 16 (резкость/лица/текст).
- Формат t2i-слоя в офиц. аннотаторе: одна строка = абзац-подпись + пробел + ОДИН JSON-массив. Ключи строки по порядку `id, bbox, desc`. id = класс-существительное + индекс слева-направо, сверху-вниз с 1 (`person_1`, `dog_2`); текстовый блок = двухбуквенный код языка + `_Text_` + N (`Ru_Text_1` — мы так и делаем).
- desc: абзац в «генеративном» залоге, начинается с сущности (никогда «the X»), БЕЗ позиции; цвет/материал/состояние/маркировка. Люди — самые богатые desc (этнос, пол, возраст, тон кожи, телосложение, волосы, лицо, каждая вещь одежды, поза, выражение). Текстовая строка: ПОЛНЫЙ текст дословно в двойных кавычках, переносы как `\n`, плюс типографика. -> наш `. Text: "..."` заменить на `"..." + шрифт/цвет`.
- Подпись цитирует КАЖДЫЙ id ровно один раз (в `<>`), без лишних id; первое упоминание — на уровне сущности («a wicker table <table_1> holding a tiered stand <stand_1>»); детали вида/текста живут в desc.
- bbox: `[y_min,x_min,y_max,x_max]` 0-1000, целые, прижаты к краям, плотно вокруг объекта, **с запасом 5-15 единиц вокруг текста**. Правило пропорций: элемент с физическим отношением ширина/высота a получает x-span ≈ y-span × a × H/W (на неквадратных холстах!). -> проверить наш планировщик на 16:9/9:16.
- >~10 однотипных предметов -> ОДНА «коллекционная» строка с точным числом и расположением; предметы, у которых важна позиция, — отдельные строки. Структурные макеты (таблицы, календари, афиши) раскладываются по регионам, каждая строка — полный дословный текст региона.
- Подпись: средний/дальний/расфокусный план — формы и силуэты, не читаемый текст; фон ≈ 1/6 подписи; без оценок («красивый») и без финальной фразы про настроение; негативы как наличие («no X» -> то, что есть); время суток = свет, не надпись; открывать конвенцией «Full-color outdoor photograph, …» / «Studio photograph, …»; добавлять пару обычных неидеальных деталей, не «сток».
- Если целевой холст не квадрат — апсемплер получает строку «TARGET CANVAS: W:H» и компонует под него.
- **Формат ПРАВКИ (аннотатор BFL):** абзац в повелительном залоге («Change the …», «Remove the delivery van <van_1>») с цитированием id и `<ref_image_N>`; в конце одна фраза «всё остальное идентично источнику». Таблица строк `{id, from, src_bbox, tgt_bbox, desc}`: `from` = `ref_image_N` или `target` (новое содержимое); `src_bbox` = null для target; `tgt_bbox` = null для удаляемого; для перемещённых/растянутых — оба; новые объекты по реальному размеру; id для текста `En_Text_N`; строки только для затронутых/якорных объектов + сцена, если меняется. Конечные состояния (новый цвет, новый текст в кавычках) — в абзаце, статичный вид — в desc.
- Обычный апсемплер правок: повелительный залог для ограниченных изменений; «Convert the entire image into…» для глобальных; «Create a photograph of …» когда референсы собираются в новый кадр (что берём из каждого по порядковому номеру); сохранять текст дословно в кавычках, на языке оригинала, при замене — «match original font, size and colour»; перечислять побочные эффекты (тени, отражения, перспектива); «what fills a removed region»; 50-150 слов; в конце — что остаётся неизменным; люди сохраняют идентичность.
- **Что делать у нас:** наш LM Studio (Gemma 26B, с vision) может исполнять роль апсемплера/аннотатора с ЭТИМИ системными промптами: для правки он видит картинку + просьбу и выдаёт абзац+таблицу src/tgt; для t2i — абзац+таблицу вместо нашей конвертации. Уже есть вес «клейн-пайплайн» (Qwen3.5-9B апсемплер BFL) — не нужен.

## Итерация 5 (поиски 12-15: KV cache, inpaint, сэмплеры, сохранение лица)
- FluxKVCache (нода ComfyUI): кэш K/V референса после шага 0, до 2.5x быстрее при нескольких референсах — но у FLUX.2 работает ТОЛЬКО с отдельным чекпойнтом 9B-KV (на обычной модели игнорирует референс -> текст-в-картинку). Для flux3 отдельного KV-чекпойнта не нашли -> НЕ включать, пока BFL не выпустит.
- Inpaint с маской: общий приём — crop-and-stitch (вырезать регион с контекстом, шумить только его, вклеить с feather и color match). У нас это уже `image_contained*`; смысл — сохранять «всё вне региона пиксель-в-пиксель». Плюс официальный путь Klein: layout-правка с src_bbox=tgt_bbox для якорей.
- Сэмплеры: независимых замеров нет. Euler/simple — стабильный дефолт; для FLUX.2 distilled: 4-8 шагов на черновик, ~25 «полировка», >25 мало что даёт. -> наш grid: 8 / 12 / 16 / 24 шага на distilled на фикс. seed (текст вывесок + лица), скорость тоже.
- Шаблон промпта правки (гайд aireiter): «Using image 1 as the base, change [one element] to [target]. Keep [identity, pose, composition, wardrobe, text, other details] unchanged.» — Change-клаузa + Preserve-клауза; у нескольких референсов назначать роли («image 2 = identity», «image 3 = outfit»).
- Лицо: в промпт НЕ описывать лицо (его держит референс/Enhancer); чёткое хорошо освещённое лицо на входе; дрейф накапливается при цепочках правок (наш rebase-after-3 из FireRed тоже полезен для Klein — проверить).
- Идентичность никогда не идеальна: для «лицо должно остаться» — Consistency LoRA + композит лица (но «no face paste-back» запрещён пользователем -> не делать).

## Итерация 6 (поиски 16-19: удаление текста, руки, refine/upscale, обучение персонажа)
- Удаление надписи: писать конечный результат («the sign face stays a plain clean surface of the same material»), не «no text»; объект первым, потом изменение, потом что оставить; другие надписи называть поимённо («keep the 'АПТЕКА' sign unchanged»), а не «preserve everything». Для чистоты — маска + crop-and-stitch (наш `image_lettering_remove`).
- Руки/пальцы на distilled: гайд (одиночный источник) — больше шагов 6-8 (у нас 16, уже ок), cfg 1.2-1.5, сэмплер res_2s; для готовых кадров — inpaint руки (наш `image_handfix`). Не подтверждено, пробовать в сетке: cfg 1.0 vs 1.3.
- Refine/upscale (Klein 9B архвиз): upscale_by 2.0 предварительным 4x-апскейлером, затем Klein steps 10, cfg 1.0, **denoise 0.15** — удерживает вход почти как есть. Общее правило: 0.15-0.3 деталь, 0.4-0.6 пересборка. У нас: можно добавить «резкость» вторым проходом KSampler denoise ~0.2 на латенте референса (без LoRA).
- Обучение персонажа (BFL + RunComfy): LR 8e-5…1e-4 (персонажу выше), 1500-3000 шагов (у нас 2000 — норм, у RunComfy 5500 шагов из «repeats»), ранг 32/32 по докам BFL (у нас 16 — A/B), разрешение 1024+, разнообразные позы/свет, придуманный триггер-токен одинаково в каждой подписи + подробные подписи, caption dropout 0.05, превью на Base: 50 шагов guidance ~4 (у нас сейчас 3.5 -> поставить 4). Если LoRA в превью слаба — сначала проверить режим сэмплирования. LoKr против LoRA: сначала чистая LoRA.
- Применение LoRA на distilled: доки BFL — сила ~0.75 (0.5-1.0); у reddit для FLUX.2 нередко 1.0-1.25.

## Итерация 7 (поиски 20-23: negative/cfg, upsampler pup, ограничения, код инференса)
- Distilled: cfg 1 → negative практически не работает (в ComfyUI edit-subgraph её нет, ZeroOut). Негатив нужен только Base (cfg 3.5-4, 50 шагов; diffusers-пример cfg 5.0).
- Промпт ≤ ~512 токенов, дальше деградация; фокус на 50-150 слов у сообщества, но BFL upsampler пишет 100-350 слов для t2i и 50-150 для edit. Субъект первым.
- Upsampler (pup, Qwen3.5-9B fine-tune, Apache 2.0, system_prompts.json: t2i / i2i / t2i_bbox / i2i_bbox) — наши сохранённые промпты в `klein_bfl_upsampler_prompts.txt` его же. Для edit без него «результаты нестабильны» (сообщество) → у нас LLM-аннотатор для edit с src/tgt боксами = главный кандидат на A/B.
- Боксы — подсказка размещения/масштаба, не маска: мелкий элемент может не появиться, элемент может выйти за бокс. Для надёжности: ≥ ~5% площади на элемент, не больше ~10 элементов на строку-таблицу (больше — одна «collection» строка с числом и раскладкой).
- Правило аспекта из системного промпта: бокс объекта с физ. отношением a получает x-span ≈ y-span · a · H/W (на широком холсте боксы шире в долях). Проверить, что наш planner делает так же.
- Мелкий текст/плотные таблицы у Klein размываются; 4B хуже 9B (у нас 5.6B). Текст: короткий капсом лучше; печатать дословно в двойных кавычках, `\n` для переносов, «режь контент, а не уменьшай шрифт».
- Разрешения: Klein чувствителен к нестандартным; держаться ~1 MP и кратности 16 (у нас `_enforce_output_size` уже).
- Edit-таблица: `from` = ref_image_N | target, src_bbox=null у новых, tgt_bbox=null у удалённых; текстовые блоки `En_Text_1`; 5-15 ед. поля вокруг текста; финальная фраза «everything else stays identical».
- Код-референс: vLLM-Omni `examples/offline_inference/flux3/end2end.py` (до 10 референсов), diffusers pipeline Flux3 (default 16 шагов без CFG).

## Итерация 8 (поиски 24-27: дрейф идентичности, Consistency LoRA, кириллица, shift/сэмплер)
- Edit-промпт: одно изменение + назначить референс + явный «keep the same facial identity, proportions, hairstyle / same pose, hand placement, camera angle». Порядок референсов держать стабильным; цепочки правок — всегда от исходника, не от последнего результата (дрейф копится).
- Consistency LoRA: во всех публичных workflow сила **0.8** (LoraLoaderModelOnly); у нас 1.0 → A/B 0.8 vs 1.0 (1.0 может «выжигать»). Размер входа ~1 MP, кратность 16.
- Дрейф лица на длинных цепочках: есть ноды Flux Identity Guidance (strength 0.30, 0–0.8) — только стандартный sampler-path; не берём пока.
- Кириллица Klein: публичных тестов нет → нужен собственный тест (фразы 1-3 слова, 3 разрешения). Опыт Flux.1: короткий текст, низкое разрешение — меньше ошибок.
- ModelSamplingFlux в доках: линейный shift по токенам (base 0.5/max 1.15); наша формула mu=ln(alpha) — отдельная ветка Flux3, не путать. res_2s = 2 вызова за шаг: сравнивать при равном времени. Distilled настроен на фиксированное расписание — выигрыш от res_2s сомнителен.

## Итерация 9 (поиски 28-31: мульти-референс, inpaint, квантование, разрешение)
- Референсы: BFL — до 4 (больше не поддерживается официально; у нас 3 + источник), у сторонних 3. Один референс = одна роль (лицо / одежда / продукт / фон), роль прописывать словами в промпте. HEX-цвета (#FFB400) Klein понимает нативно — годится для брендовых цветов в боксах/описаниях.
- Inpaint: стандартный VAE-Encode-for-inpaint — ошибка; рекомендуют Crop → Klein на квадрате маски → Stitch без VAE-круга по нетронутым пикселям. «Klein слишком послушен»: узкий промпт только про изменение, иначе меняет лицо. Для нашего layout-first/contained-edit: паста только изменённых пикселей (уже делаем) — подтверждено.
- Квантование: сравнений INT8 vs BF16 для Klein нет. FP8 4B near-lossless (LPIPS 0.06), на 9B хуже (0.13) → держать TE в BF16 для критичных кадров. Для 9B защищают блоки TE (берутся скрытые состояния слоёв 9/18/27). У нас int8 convrot UNet+TE: A/B на тексте (кириллица) с bf16 TE (он уже лежит на E:\klein_dl).
- Разрешение: BFL — до 4 MP (2048²); неофициально советуют итерировать на малом, финал 2K тем же seed; экстремальные аспекты (>16:9) обрезаются. 512 токенов предел. Шаги: 4-8 концепт, ~25 полировка (для Base).

## Итерация 10 (поиски 32-35: LoRA base→distilled, move-боксы, скорость, пластиковая кожа)

## Итерация 16 (ещё 50 поисков, 17-32)
- KV-cache модель Klein: быстрее на правках 3 МП (~53→32 с), но +VRAM (на 24 ГБ OOM/двойной RAM у части людей) и нет сравнения качества → не берём.
- Сэмплер distilled: euler + simple, ровно 4 шага (у нас 16 шагов cfg 1 по шаблону BFL), ancestral не сходится; Flux2Scheduler — предмет A/B, не трогаем.
- Photo-промпт: описывать свет физически (направление окна, мягкость), «natural skin texture, visible pores»; «8k masterpiece» не помогает.
- Consistency LoRA: рекомендуют 0.5–0.8 (диапазон 0.2–1.0), при 1.0 часть правок не применяется; у нас на A/B фон лучше при 1.0 → оставляем 1.0, но если правка «не берётся» — снижать до 0.6–0.8 (кандидат на авто-ретрай). Не спасает от сдвига света/цвета.
- Цепочки: «restate» (все изменения одной инструкцией от оригинала) лучше, чем chain; каждый round-trip VAE теряет контраст/детали — наш rebase после 3 правок + композит это закрывают.
- Датасет LoRA: BFL — 20–40 картинок, у нас 16 (риск слабой обобщаемости); трюк: подписи короткие, без перечисления черт лица, уникальный триггер; rank ≤16 даёт чистый результат при силе 0.7–1.0, rank 32 может требовать силы ниже; лучший чекпоинт — по семплам (пик часто 750–1500 шагов), у нас save_every 250.
- Размеры: кратно 16, ≤2 МП оптимально; вход >4 МП ресайзится молча.
- Два LoRA сразу (персонаж+стиль) мешают друг другу; ставить персонажа первым, силы по 0.4–0.6.
- Счёт/лево-право у Klein ненадёжны в плотных сценах → боксы + проверка VLM, не слова.
- Фильтры: репозиторий BFL содержит NSFW-фильтр входа/выхода; в нашей ComfyUI-сборке чёрный кадр — не отказ, а сбой (уже обработано в black_frame тесте).
- Мульти-вью: есть CharacterSheet LoRA (front/side/back) — полезно для датасета персонажа из одного фото, пока не берём.
